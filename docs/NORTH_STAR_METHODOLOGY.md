# CogniFold 研究方法论 — North-Star Operating System

> 这份文档只回答**"怎么研究"**,不指定"研究什么"。
> 它定义一套规则:用什么流程,把 neuroscience / cognitive science 的原理,变成**被验证过、有收益**的记忆能力。
> 受众:CogniFold 作者 + build-in-public 的读者。具体课题(TR、遗忘、双轨…)不在本文,由流程从缺口里产出。

---

## 0. 先把北极星摆正

- **北极星 = 能力**:一套 always-on、能持续积累 / 巩固 / 遗忘 / 预判、并且**可测量地帮到 agent** 的记忆。
- **类脑 = 假设来源**:大脑是"这种记忆能跑通"的存在性证明,也是取之不尽的机制库。它是**指南针 + 点子库,不是目标**。
- **推论(决定我们敢不敢扔东西)**:一个脑机制没收益就删,不背"生物保真度"的包袱。飞机不必扑翼。

---

## 1. 驱动方式:问题拉动,脑科学供给

| 角色 | 谁 | 作用 |
|---|---|---|
| **生成器** | neuroscience / cogsci | 往 backlog **供候选机制** |
| **阀门** | agent 的**实测缺口** | 决定**拉哪个、何时拉** |

- 不按"把大脑覆盖全"行军(= museum 风险,为像而做);按"哪疼修哪"拉动(= 为有用而做)。
- 这一条让"有收益就沉淀"有了方向:**带着已知的洞去脑科学里找解**,而不是广撒网碰运气。

---

## 2. 五条宪法(program constitution)

1. **程序级北极星 = 迁移宽度。** 单个实验赢不算数;一个机制要在 **≥2 个不相干任务**上复现增益,才算"沉淀"。否则只是过拟合某个榜。
2. **借用层级 = Marr 计算 / 算法层,禁实现层。** 借"它解决什么计算问题、用什么算法",不借脉冲 / 神经递质 / 具体脑区。
3. **验证阀门 = 四件套 + 预注册 kill 阈值。** 主张 / 操作化 / 隔离消融 / kill 标准,缺一不 merge;阈值**开跑前写死**。
4. **双证度量 = CogEval 结构 + 外部任务 payoff。** 两个都涨才留;只有 CogEval 涨 = 自卖自夸,一击致命。
5. **负结果公开 = kill log。** 敢挂"这个脑机制试了、没用、删了",才是 build-in-public 的可信度来源;全是成功的仓库没人信。

---

## 3. 选择机制:一条带闸门的漏斗 ★(本文核心)

```
 缺口 ─▶ ① 论文查取 ─▶ ② 调研抽象 ─▶ ③ 可行性构思 ─▶ ④ 部署前验证 ─▶ ⑤ 沉淀
(Gap)     (Lit)         (Abstract)      (Feasibility)     (Pre-deploy)      (Ledger)
  │          │              │                │                 │
  └──────────┴──────────────┴────────────────┴─────────────────┘
                      任一闸门失败 → Kill log(公开)
```
**设计原则:便宜的死在左边(纯纸面),贵的(工程 + 算力)只花在过了 ③ 可行性闸门的候选上。** 每一阶段都有明确的**产出物**和**go / no-go 闸门**。

---

### Stage 0 — 缺口入口(Gap intake)
- **目的**:候选机制只能从**真实、可测**的缺口诞生,不从"感觉很类脑"诞生。
- **做什么**:把症状定位成一个指标(某 benchmark 的弱项 / 一簇失败 case / always-on 愿景需要但当前缺的能力)。
- **产出**:`gap ticket` — 症状 + 量化它的指标 + 当前基线值。
- **闸门**:这是个**可量化的真缺口**吗?(不是 vibe)

### Stage 1 — 论文查取(Literature retrieval)
- **目的**:针对该缺口,在脑科学 / 认知科学里找解决**同类计算问题**的机制。
- **做什么**:
  - 检索词用**认知功能 / 问题**的词,不用我们代码的词(搜 `memory consolidation` / `active forgetting` / `event segmentation`,而不是 `graph dedup`)。
  - **先综述定地形**,再用 seed paper 顺前向 / 后向引用扩(Semantic Scholar / Connected Papers / Google Scholar / arXiv)。
  - 优先 **canonical、被反复验证**的源;警惕单篇新奇结论。
  - 允许 LLM 辅助快速综述,但**每条主张回原文核对**(防二手转述失真)。
- **产出**:3–8 篇**带注释的小书目** + 一句话候选机制描述。
- **闸门**:存在**机制级**(算法层)描述,而非只有"现象"。

### Stage 2 — 调研抽象(Survey & abstraction)
- **目的**:把机制剥到我们能实现的层。
- **做什么**:用 Marr 三层提炼——它解决**什么计算问题**?用**什么算法**解?剥掉实现层(脉冲 / 递质 / 脑区)。
- **产出**:`mechanism card` —
  (a) 认知主张 + 引文;(b) 它解决的计算问题;(c) 可实现层的算法;(d) **它预测什么会变好**(连回 Stage 0 的指标)。
- **闸门**:能落到算法层 **且** 该层能映射到我们的基元(图操作 / 打分 / agent)。

### Stage 3 — 可行性构思(Feasibility & operationalization)★ 最关键的廉价淘汰口
- **目的**:在**不写正式代码**的前提下,判断"值不值得做、能不能干净测"。
- **做什么**:
  - 把机制映射到 CogniFold 真实基元(`node/edge ops`、`scoring`、`consolidation`、`retrieval`)。
  - 设计**最小改动** + **最小消融**(with / without)。
  - 估**成本**(LLM 调用量、延迟、复杂度)与**冲突风险**(和现有 op 打架?)。
- **产出**:一页 `design doc` — 具体操作 / A-B 设计 / 该动的指标 / 预期效应量 / 成本。
- **闸门**:**可行性 × 可干净测量(消融能隔离机制) × 预期收益**。**大多数候选应在这里死掉**——纸面推理就能判,不烧工程。

### Stage 4 — 部署前验证(Pre-deployment validation)★ 防"纸面有、实测无"
- **目的**:在**并入主系统之前**,隔离验证机制真的有用。
- **做什么**(顺序不可省):
  1. **预注册**:开跑前冻结 假设 / 指标 / keep 阈值(= kill 标准)/ 消融设计。
  2. **最小原型 + 触发自检**:在 branch / sandbox 实现,小切片 smoke,**先确认"机制真的触发了"**——核对它声称产出的 artifact 真的出现了(教训:曾有"intent 列纸面填了 2–22、实测全 0")。
  3. **隔离消融**:同 seed、同其它一切,A/B 跑 **CogEval 结构探针 + 外部任务切片**。
  4. **双证 + 显著性**:结构与任务**都**超过噪声(多 seed / 置信区间)。
  5. **成本 / 回归检查**:没爆延迟 / 成本,没回退其它已沉淀指标。
- **产出**:`validation report`(预注册 + 结果 + 判决)。
- **闸门**:达预注册阈值 + 双证通过 + 无不可接受回归 → 升级 Stage 5;否则 → **Kill**。

### Stage 5 — 沉淀(Deploy & consolidate)
- **目的**:把幸存机制变成系统的永久能力,且**不可被未来改动静默破坏**。
- **做什么**:合入主干;登记进 `validated-mechanism ledger`;**把它的探针加进永久回归套件**。
- **产出**:已合入代码 + ledger 条目 + 常驻 probe。

### Kill & 负结果(贯穿全程)
- 任一闸门失败 → `kill log` 条目:**是什么 / 为何挂 / 证据**。公开。

### 定期 re-audit
- 已沉淀机制会因**机制间交互 / 数据漂移**失效 → 定期重跑常驻 probe,失效的降级或移除。

---

## 4. 产物清单(artifacts,即"研究在产出什么")

| 阶段 | 产出物 | 性质 |
|---|---|---|
| 0 | Gap ticket | 缺口 + 量化指标 |
| 1 | 注释小书目 | 候选来源 |
| 2 | Mechanism card | 算法层机制 + 预测 |
| 3 | Design doc | 操作 + 消融 + 成本 |
| 4 | Validation report | 预注册 + 结果 + 判决 |
| 5 | Ledger 条目 + 常驻 probe | 沉淀的能力 |
| 任意 | Kill log | 负结果(公开) |

---

## 5. 节奏(cadence)

- **每周**:推进若干候选过漏斗;**至少一条产出 verdict**(promote 或 kill);build-in-public 更新 ledger + kill log。
- **多数候选止于 Stage 1–3**(便宜),只有少数进入 Stage 4(烧算力)。
- **定期**:re-audit 已沉淀机制。

---

## 一句话

**让问题驱动、让脑供给;每个机制都过"可行性"廉价闸和"部署前验证"硬闸;成功(迁移宽度)与失败(kill)两个标准都量化、都公开。** 把这套流程钉死,"下一步研究什么"会从缺口里自己冒出来。
